## 三、发现并修复的缺陷（本轮新增）

### 3.1 【严重】跨午夜会话造成折间泄漏

**证据**：真实快照上 **3 个反馈会话跨 UTC 午夜**、1 个跨本地午夜；3 个会话的窗口落在多个日期上。

**旧行为**：按日历日期分组 → 同一会话的窗口进入不同折，模型在自己见过的行上被评分。日期数被虚报为 10，实际独立日期块只有 **8**。

**修复**：新增 `train/grouping.py`，用并查集把"被同一会话跨越的日期"合并为一个日期块；评估与训练都按日期块排除留出行（`v2.py` 的 `sup_groups`）。跨午夜会话现在整体进同一折。

### 3.2 【严重】窗口级权重让长会话主导训练

**证据**：单个真实会话最多贡献 **153** 个窗口，中位数仅 **6** → 权重差 **25 倍**。总监督权重 2900.1 中，绝大部分来自"一个用户的一次判断"。

**修复**：会话均衡权重——每个反馈会话总共贡献 1.0，在其窗口间分摊；辅助窗口标签共享一个有上限的总预算（显式总权重的 1.0 倍），不再每条固定 0.8。总权重从 2900.1 降到 **64.0**，单个会话不再能压倒其余。

### 3.3 【严重】评估权重与部署权重不一致（本轮引入后自查修复）

第一次实现只把会话均衡权重放在评估器内部计算，`pipeline.py` 部署时仍用旧的窗口权重 → **指标无法描述实际发布的模型**。已改为在 `prepare_v2_training_data` 里一次算好，评估与部署共用同一份（`group_ids` / `date_groups` / `sample_weights` 随数据对象传递）。

> 这个问题由消融实验暴露：E1a 与 E1b 数值完全相同，说明注入的权重被忽略了。**没有那次对照，这个不一致会一直留着。**

### 3.4 【中】规则基线按列号硬编码

`_rule_probabilities` 用 `X[:, 0] / X[:, 3] / X[:, 14]` 取特征。任何列序变化都会**静默**读错特征（而不是报错），删列的消融直接崩溃。已改为按特征名解析，缺列时显式抛错；提取不到行为特征时规则基线标记为 `unavailable` 而非编造。

### 3.5 【严重】`task_type_code` 是死特征

**证据**：快照中 8,198 个 V3 窗口的 `task_type_code` **全部为 0.0**（`f24` 列同样只有 0.0 一个取值）。它在 `telemetry_features.py` 里被硬编码为 `0.0` 写死。

**影响**：24 维 V3 向量里有 1 维是常量，模型学不到任何东西，却占了"任务类型"这个语义位置。

### 3.6 【严重】浏览器特征结构性恒零

**证据**：`browser_segments` 表 **0 行**；`browser_ratio > 0` 的窗口 **0 / 8198**。

**影响**：`browser_ratio`、`audible_browser_ratio`、`top_domain_ratio`、`domain_switch_count` 四项恒为 0。**更糟的是无法区分"用户没浏览"与"浏览器采集未接入"**——两者在特征里长得一模一样。这正是本轮要建立质量记录的原因。

### 3.7 【中】实验脚本重建窗口时丢弃浏览器段

`scripts/run_experiments.py:108` 以 `[]` 调用 `build_v2_feature_window`，而在线路径传真实浏览器段（`telemetry_service.py:452`）。经该脚本重建的窗口与线上窗口**特征口径不一致**。

### 3.8 【严重】常规重算会抹掉用户窗口标签

**证据（已在真实快照副本上复现）**：`upsert_feature_windows` 的冲突分支把 `label = excluded.label`，而 rollup 每次都提交 `label=None`（"我没有新标签"）。调度器会反复重算重叠区间，所以一个已标注窗口被再次 roll 到时，用户标签被写成 NULL：

```
label before: focus -> after: None      # 复现输出
```

快照中 **2,981 个窗口带用户标签**（focus 2,273 / distracted 708），全部处在被后台任务擦除的风险中。这直接破坏本阶段要建立的高质量数据闭环。

**修复**：冲突分支改为 `label = coalesce(excluded.label, existing.label)` —— 重算不再能清除标签，只能写入新标签；清除必须是显式操作。`quality_json` 同样用 coalesce（有新观测才刷新，旧调用方不会把它抹空）。

**验证（修复前 / 修复后 对比，脚本 `label_erase_repro.py` 可复跑）**：

| | 修复前 | 修复后 |
|---|---|---|
| 单个已标注窗口重算后 | `focus` → **`None`（标签被抹掉）** | `focus` → `focus`（保留） |
| 全库标注窗口（2981 个）重算后 | 标签丢失 | `labels_lost = 0`，`conclusive = true` |

新增 3 项回归测试（重算保标签、重算可写新标签、质量记录落盘）。

> **过程教训**：这个复现脚本第一版写了一处错误的调用方法名、异常被 `except` 吞掉，于是输出 `reproduced: false` ——一个**假阴性**。已改为记录 `insert_error` 并输出 `conclusive` 字段：无法执行时必须报告"不确定"，而不是报告"未复现"。

> 这一项**不在上一轮交付清单中**，是本轮在接入质量记录时顺带发现的既有缺陷。

## 四、诊断：为什么 BA 低于随机（本轮最重要的结论）

修正分组后 BA 反而下降（0.359 → 0.244）。逐项排查：

**标签映射没有反**：`focus` → 1，567 条显式样本中 270 条为正类，映射正确。

**真正原因是"日期身份"主导标签**：每个反馈日的专注率从 **3.4% 到 100%**，跨日标准差 0.428。

| 日期 | 样本 | 专注率 |
|---|---|---|
| 2026-07-24 | 2 | 1.000 |
| 2026-07-25 | 31 | 0.065 |
| 2026-07-26 | 104 | 0.644 |
| 2026-07-27 | 153 | 0.902 |
| 2026-07-28 | 88 | 0.034 |
| 2026-07-29 | 95 | 0.053 |
| 2026-08-02 | 35 | 1.000 |
| 2026-08-03 | 49 | 0.163 |
| 2026-08-04 | 5 | 1.000 |
| 2026-08-05 | 5 | 1.000 |

效应量最大的特征也是日历位置：`weekday_cos` (d=+1.02)、`weekday_sin` (d=-0.93)、`hour_cos` (d=+0.66)。

**特征组消融**（同一批 567 条显式样本、同一分组与权重）：

| 特征集 | 特征数 | BA | minority F1 | Brier | AUC | 折稳定 |
|---|---|---|---|---|---|---|
| 全部 24 维 | 24 | 0.2598 | 0.3059 | 0.5681 | 0.1624 | ✗ |
| 去掉日历 4 维 | 20 | 0.2200 | 0.2575 | 0.5913 | 0.1350 | ✗ |
| **只用日历 4 维** | 4 | **0.5367** | 0.6609 | 0.3496 | 0.3902 | — |

**结论（必须如实说明）**：

1. 去掉日历特征后，行为特征单独表现 **低于随机**（BA 0.22, AUC 0.135）——当前 20 维行为特征在**留出日期**上没有可迁移的判别信号。
2. 只用日历特征反而"看起来最好"（BA 0.537），但它的 AUC 只有 0.39（低于 0.5），混淆矩阵 `[[24,273],[2,268]]` 显示它几乎全预测为正类——这是**退化预测器**在类别不均衡下骗到的虚高 BA，不是能力。它的"折稳定通过"也来自同样的退化。
3. 因此：**当前数据不足以支撑一个可上线的分心识别模型**。这不是调参或加特征能解决的，而是反馈量与标注质量的问题。

这直接决定了本轮后续工作的重点：**优先把数据闭环和标注契约做对，而不是继续堆特征**。

## 五、已落地的契约与代码

### 5.1 数据质量记录（新增）

`services/window_quality.py`：`WindowQuality` 记录每个窗口的

- 各采集源**是否启用**、**是否实际可用**；
- 各源**观测秒数与覆盖率**、**缺口秒数**、**是否中途恢复**；
- 事件数 / 交互桶数 / 浏览器段数；
- `quality_tier`（`full` / `partial` / `activity_only` / `empty`）。

`feature_observed(name)` 按**特征名 → 数据源**映射判断该特征这次是否"有机会"非零。**未启用采集时的 0 不再等同于观测到的 0。**

### 5.2 标签契约（新增）

`domain/label_contract.py` 把三个问题显式分开：

| 问题 | 类型 | 用途 |
|---|---|---|
| 当时是否分心 | `StateLabel` | 状态模型训练 |
| 提醒有没有帮助 | `HelpfulnessRating` | 干预评价 |
| 提醒是否打扰 | `IntrusivenessRating` | 提醒策略 |

新增可选上下文：`context_type`（任务执行 / 任务查阅 / **主动休息** / 其他 / unknown）、`goal_alignment`（符合 / 偏离 / 不确定 / unknown）、`label_source`（用户确认 / 窗口标注 / 规则推断 / LLM 辅助 / unknown）。

关键不变式（已测）：
- 缺失一律 `unknown`，**不用默认值伪造**；
- `break` 不参与状态监督（`is_state_supervision('break', …) == False`）；
- `break` 只影响提醒保护（`protects_from_reminders('break') == True`）；
- `mixed` 同样不进状态监督。

### 5.3 数据库迁移

`0026_add_task_context_and_quality.py`：新增 `context_type`、`goal_alignment`、`label_source`、`quality_json` 四个可空列 + 一个索引。历史行保持 NULL（读作 unknown）。仅在临时库验证，**未对正式库执行**。

### 5.4 分组与权重（新增/修复）

`train/grouping.py`：日期块并查集合并、会话均衡权重、辅助标签总预算。评估与部署共用同一份计算。
