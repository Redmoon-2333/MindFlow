## 数据质量契约

- 活动、输入桶和浏览器片段按窗口裁剪，并以时间区间并集计算覆盖；重复投递不会增加覆盖。
- 输入桶使用真实 `window_start_utc + duration_s`，并兼容显式 end；跨窗覆盖不会丢失，V3 聚合计数仍按桶起点归属，不重复计数。
- 覆盖是 payload 覆盖，不等同于采集器 uptime；部分观测不能解释为整窗完整观测。
- `uncovered_seconds` 表示无 payload 覆盖时长；`gap_seconds` 没有心跳证据时为 null，明确关闭的来源为 0，不伪造采集故障。
- 历史开关或可用性没有证据时为 JSON `null`，不是自动填为 False 或 True。
- 活动运行记录仅提供“曾启用”的证据；辅助采集器状态不能根据活动采集器状态推断。
- 区间查询包含窗口开始前启动的持续运行，并按用户隔离；合成 coverage_gap 记录不充当真实采集器。
- 本轮保持特征 schema v3；质量记录随窗口保存，不谎称 V4 缺失值建模已经完成。
- 在查询前对齐五分钟窗口，避免从非对齐时间重滚时损坏已有完整窗口。

## 复核追加项

- 内部校准拆分必须分别重算基础训练和校准子集的辅助监督预算；只在外层折重算不足以满足契约。
- 连续取消训练任务或关闭协程时，必须等待实际训练线程结束并完成发布或回滚，不能关闭后仍写 active 指针。
- 聊天服务层的会话排队必须计入总超时，异常日志不能泄漏供应商原始正文；历史读取必须按用户隔离。
- 训练就绪界面必须反映校准可用性与合并后的独立日期组，不以原始反馈天数代替可评估性。
- 供应商与图层的合成 key/reasoning 哨兵泄漏已独立复测关闭；这不是实际生产密钥泄漏事件的认定。
- 重复分析的非 owner 不能因取消、超时、降级或缓存重放改写主请求状态、覆盖分析结果或释放预算。
- 聊天历史加载和生成回复均使用对话代数校验；旧请求成功或失败不能覆盖新会话。
