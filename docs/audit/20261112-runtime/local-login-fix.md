# 本机页面登录修复验收

日期：2026-11-12，Asia/Shanghai。

## 问题与修复

直接访问正式界面后点击“进入 MindFlow”，页面原先向
`/api/v1/auth/bootstrap/ticket` 发送未认证请求，得到 401。
该接口只为已认证启动器签发票据，开发环境通过 Vite 代理补充凭证；
正式静态界面没有这一代理，因而不能复用相同登录流程。

最终实现使用独立的 `POST /api/v1/auth/local-session`。
正式界面的按钮在当前标签页建立 HttpOnly 本机会话，无需调用外部应用。
`localhost` 与 `127.0.0.1` 分别在各自访问地址完成登录。
桌面启动器与开发环境保留原有票据流程，主令牌不进入页面或 URL。
登录状态变化后收到新的启动票据 hash，界面也会重新处理。

## 本机访问边界

本地会话入口同时要求：

- 请求的实际连接来源为回环 IP，Host 为 localhost、127.0.0.1 或 ::1。
- Origin 与接收请求的协议、主机和端口完全一致。
- Fetch Metadata 为 same-origin / same-origin / empty。
- JSON Content-Type 和显式的 `X-MindFlow-Login` 请求头。

缺少任一条件返回 403，不创建 Cookie。原 `/auth/bootstrap/ticket`
仍拒绝匿名调用，一次性票据仍不可重放。会话 Cookie 继续使用 HttpOnly、
SameSite=Strict 和 `/api` 路径，登录响应禁止缓存。

此入口面向单用户桌面：能在同一电脑运行任意本机程序的用户不在浏览器来源隔离的保护范围内。
它不构成远程身份验证，也不适用于多人共享或公网部署。
产品未增加外部应用协议、浏览器安全设置例外或主令牌披露。
