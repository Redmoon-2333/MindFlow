修正评估口径后的消融（同一快照、同一日期折，567 个显式样本）：

四个变体质量门全部不通过，折稳定性全部 false。**结论：当前 ML 不应上线**，保持 shadow。

## 三补、迁移中自查发现并修复的两个问题

**必须说明的是，这两项在单元测试全绿（2303 项）时依然存在，只有真实调用才暴露**：

1. **ECNU 路径一度丢失 JSON 输出模式** — 第一版适配器让两档共用实例且不带 `response_format`，面板专家的 JSON 约定失效。已修复（`chat` 档恢复 JSON 模式，两档独立实例），修复后真实面板路径调用返回字段齐全的 JSON。
2. **显式 base_url 被环境里的 ECNU 模型名劫持** — 已修复为显式 URL 优先。

两项都补了回归测试。这条经验对本项目的含义：**"测试通过"不能替代"真实链路跑通"**，ECNU 相关改动应保留一次真实调用验证。

## 四、需要你知道的两个判断

1. **模型不能上线，这不是调参能解决的**。567 个显式样本、10 个反馈日、每类样本勉强达标，但折间波动大（BA 范围 0.40）。继续收集真实反馈比调参更有价值。**不要为了"达标"降低质量门**。

2. **辅助窗口标签与用户真实判断不同分布**。窗口标签 focus 率 76.5%，显式反馈 focus 率 47.6%。这既解释了为什么"仅辅助标签训练"在显式评估上反而最好（它学到了辅助标签的分布），也说明把它并入评估会系统性高估模型。已按规范分离，并单列报告。

## 六、回滚

不得将“回滚某轮变更”等同于丢弃整个工作区。先确认目标提交和未提交改动，
备份并保存其他工作；已发布代码使用针对目标提交的 revert 流程，重新测试后发布。
供应商配置恢复须由用户确认目标配置，不能盲目覆盖当前 `.env`。
数据库降级仅在独立副本验证并备份后进行。
模型回滚必须经过版本校验及运行时引用更新，不能只手工改写 `latest.json`。
